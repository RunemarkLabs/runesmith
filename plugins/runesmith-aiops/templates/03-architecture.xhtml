A goal, step by step

  1. The planner writes a task with Acceptance and gives the owner a /goal line.
  2. The owner pastes it into Claude Code.
  3. Claude Code writes a goal status comm first, works each task on its own branch, and merges into dev when tests pass.
  4. Each task gets a reply that starts with a STATUS line: complete, partial, blocked or failed.
  5. Claude Code prints one banner and stops.
  6. The planner checks comms: verifies each reply against the repository, archives finished work, logs the outcome.

Promotions

dev to qa to beta to main, one step at a time, only on the owner's word. Before qa, the full test suite runs against dev. At qa, the owner works through the project's QA checklist page; every item must pass before beta. A failing item becomes a fix task and a GitHub issue. Build numbers are MAJOR.MINOR.BUILD with a four-digit build, one per finished goal.

Atlassian calls

  1. The planner reads the keys from the workspace .credentials and builds a Basic auth header for one command.
  2. It calls {ATLASSIAN_API_URL} on the current Cloud endpoints.
  3. Pages are drafted in markdown, converted to storage format, and published only on the owner's approval.
  4. Claude Code reads Jira with its own read-only token. To move a ticket, it asks the planner through a comm.
